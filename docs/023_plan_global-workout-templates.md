# 023 — План: глобальные шаблоны и дефолтная конфигурация

## Цель

Дать администратору и ресепшену управлять общими шаблонами тренировок,
показать их тренерам, наполнить систему дефолтными шаблонами/упражнениями/
тренажёрами и перевести удаление шаблонов и упражнений в мягкий режим.

## Шаги

1. **Prisma + миграция**
   - `WorkoutTemplate`: `trainerId` → nullable, добавить `gymId?`, `createdById?`,
     `isActive`, `archivedAt`, `defaultKey? @unique`.
   - `Gym`: связь `templates`; `User`: связь созданных шаблонов.
   - `Exercise`: `isActive`, `archivedAt`.
   - Индексы: `WorkoutTemplate(gymId,isActive)`, `WorkoutTemplate(isActive)`,
     `Exercise(isActive)`.
2. **Дефолтная конфигурация**
   - Модуль `src/default-config/default-config.ts` с идемпотентной функцией
     `ensureDefaultConfiguration(prisma, createdById?)`.
   - 3 глобальных шаблона: «Вес вверх», «Вес вниз», «Тонус».
   - Дефолтные упражнения и популярные тренажёры; тренажёры добавляются в
     каждый существующий зал без дублей по имени.
   - Вызов из `prisma/seed.ts`.
3. **API**
   - Ответ шаблона: `scope`, `gymId`, `gymName`, `createdById`, `isActive`.
   - TRAINER: список/чтение глобальных + шаблонов своих залов + личных;
     изменение/удаление только личных.
   - ADMIN: `/admin/templates` CRUD, `gym_id` опционален (null = глобальный).
   - RECEPTION: `/reception/templates` CRUD только для своего зала.
   - Создание тренировки разрешает доступный тренеру шаблон.
   - Удаление шаблона — soft delete; удаление упражнения — soft delete.
4. **Демо-данные**
   - `DemoService.load()` вызывает дефолтную конфигурацию.
   - `DemoLoadResult` дополняется счётчиками дефолтных сущностей.
   - `DemoService.clear()` не удаляет дефолтную конфигурацию.
5. **Web-admin**
   - Страница «Шаблоны» для ADMIN и RECEPTION.
   - Роуты и пункты меню.
6. **Mobile**
   - Модель шаблона получает `scope`/`gymId`.
   - Общие шаблоны видны тренеру, но не редактируются/не удаляются; личные —
   как раньше. Общий шаблон можно применить в конструкторе тренировки.
7. **Тесты и фиксация**
   - e2e: доступ ADMIN/RECEPTION/TRAINER, soft delete, идемпотентность seed.
   - `docs/023_tests_*`, `docs/readme.md`, `docs/023_result_*`.

## Критерии готовности

- Тренер видит глобальные, шаблоны своего зала и личные; чужие личные — нет.
- ADMIN создаёт глобальный шаблон и шаблон конкретного зала.
- RECEPTION создаёт/меняет/архивирует только шаблоны своего зала.
- Повторный seed не создаёт дублей.
- «Вес вверх», «Вес вниз», «Тонус» есть после seed и в демо-данных.
- Удалённые шаблон/упражнение исчезают из списков, но записи сохраняются в БД.
- Сборка backend проходит, e2e-тесты зелёные.
