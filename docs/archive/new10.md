# New 10 — план: справочник целей и отчёты по посещаемости/тренажёрам/тренерам

Дата: 2026-11-12
Запрос: «добавь в планы клиентам добавить цель из справочника отдельную вкладку для
заполнения; админу и рецепшен и тренеру добавить отчеты по посещаемости, по видам
тренажеров какой клиент как часто занимается на тренажере чтобы видеть на каком
меньше всего занимаются на каком больше чтобы можно было посмотреть отчеты по
динамике, отчет по тренеру сколько посещений его клиентов».

## Что запланировано

- Справочник целей (глобальный) и отдельная вкладка «Цель» у клиента в мобильном
  приложении; выбор цели вместо свободного текста.
- Отчёты в web-admin для `ADMIN`, `RECEPTION`, `TRAINER`:
  посещаемость, использование тренажёров (по типам и по конкретным тренажёрам),
  посещения клиентов по тренерам.
- Динамика по периодам в отчётах.
- Реализацию не начинать без отдельного согласования.

## Что сделано

- Создан `docs/plan6.md` с пунктами:
  1. справочник целей и вкладка «Цель» у клиента;
  2. отчёт по посещаемости;
  3. отчёт по тренажёрам;
  4. отчёт по тренеру;
  5. доступ тренера в web-admin к отчётам;
  6. тесты и документация.
- Зафиксировано текущее состояние кода:
  - `Client.goal` — свободный текст (`backend/prisma/schema.prisma:141`);
  - `CREATE`/`UPDATE` клиента принимают `goal` строкой
    (`backend/src/clients/dto/create-client.dto.ts:60-64`);
  - у клиента 5 вкладок, цели нет
    (`mobile/lib/features/client/client_home_screen.dart:38-44`);
  - `ReportsController` разрешает `CLIENT`, `TRAINER`, `ADMIN`, без `RECEPTION`
    (`backend/src/reports/reports.controller.ts:18`);
  - web-admin пускает только `ADMIN`/`RECEPTION`
    (`web-admin/src/router.tsx`, `ALLOWED_ROLES`), поэтому доступ тренера к
    отчётам вынесен отдельным пунктом плана.
- Зафиксированы принятые решения: посещение = `DONE`; глобальный справочник;
  группировка по типам и конкретным тренажёрам; отчёты в web-admin для трёх ролей.
- Выполнен `docs/plan6.md` (backend + web-admin; мобильное приложение по плану
  не затрагивалось).

### Backend

- Prisma: добавлена модель `Goal`; у `Client` появилось `goalId` (FK→Goal) при
  сохранении legacy-поля `goal`. Миграция `20261112120000_goals` создаёт
  справочник, переносит существующие текстовые цели и связывает клиентов.
- Новый модуль `backend/src/goals/`: CRUD `/admin/goals` (ADMIN), справочник
  `/goals` (активные), `/client/goal` (GET/PUT для CLIENT).
- `ClientResponse`/`TrainerClientResponse`: `goal` — объект `{id,name,description}`
  или `null`, добавлен `goalText` (legacy).
- `CreateClientDto`/`UpdateClientDto`: добавлен `goalId` с проверкой активной цели.
- Отчёты `GET /reports/attendance`, `/reports/equipment-usage`,
  `/reports/trainers` с ролевым скоупом: ADMIN — все залы, RECEPTION — свой зал,
  TRAINER — только свои клиенты/тренер. Визит = `Workout.status DONE`.
- `resolveClientId` ужесточён: RECEPTION проверяет принадлежность клиента залу.

### Web-admin

- Страница «Цели» (`/protected/goals`) — CRUD справочника.
- Формы клиентов (ADMIN и RECEPTION) выбирают цель из справочника; в таблицах
  показывается название цели.
- Страницы отчётов: посещаемость, использование тренажёров, тренеры
  (`/protected/reports/*`) с фильтрами периода/зала/тренера/клиента и динамикой.
- TRAINER добавлен в `ALLOWED_ROLES`; для тренера домашняя страница — отчёт по
  посещаемости, в меню только отчёты.

### Документация и тесты
