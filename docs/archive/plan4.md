## 1. BUG-2.3 — уникальные пароли и смена пароля (P0)

Проблема: всем клиентам, тренерам и ресепшену выдаётся один `DEFAULT_CLIENT_PASSWORD`,
`initial_password` возвращается в ответе API, эндпоинта смены пароля нет.

- [ ] Генерировать уникальный случайный пароль при создании клиента, тренера и ресепшена.
  - `backend/src/clients/clients.service.ts:314-319` (`getInitialPassword`)
  - `backend/src/trainers/trainers.service.ts:214-220` (`getInitialPassword`)
  - `backend/src/receptions/receptions.service.ts:63-67`
- [ ] Показывать пароль один раз в ответе на создание, не хранить в открытом виде.
- [ ] Добавить `POST /api/v1/auth/change-password`:
  - проверка старого пароля;
  - хеширование нового (bcrypt 12+);
  - инвалидация всех refresh-токенов пользователя.
  - `backend/src/auth/auth.controller.ts`, `backend/src/auth/auth.service.ts`
- [ ] Добавить сброс пароля администратором (опционально, решить до реализации).
- [ ] Тесты: `backend/src/auth/auth.e2e-spec.ts` (смена пароля, неверный старый пароль),
  уникальность паролей при создании.
- [ ] Обновить `docs/api.md`.

Критерий приёмки: два новых клиента получают разные пароли; после смены пароля старый
refresh-токен не работает; вход со старым паролем возвращает 401.
