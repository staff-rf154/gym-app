# Plan 5 — блокировка результатов после завершения тренировки

Дата создания: 2026-11-12
Источник: запрос «есть начало тренировки Начать и есть конец Закончить, после этого
нельзя менять результаты выполнения ни в мобильном приложении, ни где и никто».
По ходу работ отмечай пункты `[x]`.

## 1. Начало и завершение тренировки + запрет изменения результатов (P0)

Требование: у тренировки есть явное начало («Начать») и конец («Закончить»). После
нажатия «Закончить» результаты выполнения нельзя изменить ни клиенту в мобильном
приложении, ни тренеру, ни администратору — ни через API, ни через любой интерфейс.
Ограничение обеспечивается на backend, UI-скрытие вторично.

Текущее состояние:

- `WorkoutStatus` уже есть: `PLANNED`, `IN_PROGRESS`, `DONE`, `SKIPPED`
  (`backend/prisma/schema.prisma:37`, поле `status` — `backend/prisma/schema.prisma:279`).
- Эндпоинтов начала/завершения нет; клиент может менять результат в любой момент:
  `PUT /api/v1/client/workout-items/:id/result`
  (`backend/src/workouts/workouts.controller.ts`, `ClientWorkoutItemsController`).
- `updateItemResult` делает `upsert` без проверки статуса тренировки
  (`backend/src/workouts/workouts.service.ts:344`).
- `updateWorkout` позволяет тренеру менять тренировку без проверки статуса
  (`backend/src/workouts/workouts.service.ts:212`).
- В мобильном приложении один экран с кнопкой «Сохранить результаты», кнопок
  «Начать»/«Закончить» нет (`mobile/lib/features/client/workout_day_screen.dart`).

### Backend

- [x] Добавить `POST /api/v1/client/workouts/:id/start` (роль `CLIENT`;
  тренерская версия — п. 2):
  - доступно только владельцу тренировки;
  - переход `PLANNED → IN_PROGRESS`;
  - повторный вызов для `IN_PROGRESS` — `409 Conflict` (или идемпотентный `200`,
      решить при реализации);
  - для `DONE`/`SKIPPED` — `409 Conflict`.
- [x] Добавить `POST /api/v1/client/workouts/:id/finish` (роль `CLIENT`;
  тренерская версия — п. 2):
  - доступно только владельцу тренировки;
  - переход `IN_PROGRESS → DONE`;
  - вызов из `PLANNED` — `409 Conflict` (сначала «Начать»);
  - повторный вызов для `DONE` — `409 Conflict`.
- [x] `updateItemResult` (`backend/src/workouts/workouts.service.ts:344`):
  - разрешать изменение только при `status = IN_PROGRESS`;
  - для `PLANNED` — `409` «сначала начните тренировку»;
  - для `DONE`/`SKIPPED` — `409` «результаты завершённой тренировки изменять нельзя».
- [x] `updateWorkout` (`backend/src/workouts/workouts.service.ts:212`):
  - запретить изменение состава упражнений и плана при `DONE`/`SKIPPED`;
  - вернуть `409` с понятным сообщением.
- [x] Проверить остальные точки записи `WorkoutItemResult` (создание тренировки,
  seed, демо-данные) — блокировка должна применяться только к пользовательским
  изменениям завершённой тренировки, не ломая seed/демо-загрузку.
- [x] Схема БД: миграция не требуется, используется существующий `status`.
  При необходимости аудита добавить `startedAt`/`finishedAt` отдельной задачей
  (в текущем объёме не обязательно).

### Мобильное приложение

- [x] `mobile/lib/features/client/workout_day_screen.dart`:
  - для `PLANNED` — кнопка «Начать тренировку»; поля ввода заблокированы до старта;
  - для `IN_PROGRESS` — поля активны, кнопки «Сохранить результаты» и
    «Закончить тренировку»;
  - для `DONE`/`SKIPPED` — все поля только для чтения, кнопок сохранения и
    завершения нет, статус «Выполнена»/«Пропущена»;
  - перед «Закончить» — подтверждение, после успеха обновить календарь
    (`clientMonthWorkoutsProvider`).
- [x] `mobile/lib/features/client/client_workouts_api.dart` — методы `startWorkout`,
  `finishWorkout`.
- [x] `mobile/lib/features/client/client_workout_models.dart` — при необходи-
  мости добавить признак `isLocked` (геттер по статусу), не дублировать логику.

### Web-admin

- [x] Убедиться, что в web-admin нет формы редактирования результатов завершённой
  тренировки; если есть — скрыть/заблокировать и полагаться на `409` от backend.

### Тесты и документация

- [x] Новый e2e-файл `backend/src/workouts/workout-lock.e2e-spec.ts`:
  - клиент начинает тренировку: `PLANNED → IN_PROGRESS`;
  - до старта `PUT result` возвращает `409`;
  - после старта `PUT result` сохраняет результат;
  - после `finish` статус `DONE`, повторный `PUT result` — `409`;
  - повторный `start`/`finish` — `409`;
  - чужой клиент не может начать/завершить тренировку (`403`);
  - тренер не может изменить тренировку в статусе `DONE` (`409`);
  - `SKIPPED` также блокирует изменение результатов.
- [x] Обновить `docs/api.md`: новые эндпоинты, коды `409`, правило блокировки.
- [x] В `docs/er.md` зафиксировать жизненный цикл
  `PLANNED → IN_PROGRESS → DONE` и неизменяемость после `DONE`/`SKIPPED`.

Критерий приёмки:

- клиент может начать тренировку только из `PLANNED`, завершить — только из
  `IN_PROGRESS`;
- после завершения ни один клиентский, тренерский или административный запрос не
  изменяет `WorkoutItemResult` (ответ `409`);
- в мобильном приложении завершённая тренировка открывается только для чтения;
- все e2e-тесты и проверки линтеров/сборок проходят.

## 2. Старт тренером и клиентом, пошаговое выполнение, несколько клиентов сразу

Требование: и тренер, и клиент в мобильном приложении должны нажать «Начать
тренировку». После старта открываются задания и выполняются поэтапно. Тренер может
одновременно работать сразу с несколькими клиентами.

Текущее состояние:

- старт/завершение сейчас проектируются только для клиента (п. 1);
- запись результатов доступна только роли `CLIENT`
  (`ClientWorkoutItemsController` в `backend/src/workouts/workouts.controller.ts`);
- в мобильном приложении нет тренерского экрана проведения тренировки.

### Backend

- [x] Разрешить `POST /client/workouts/:id/start` и `finish` роли `CLIENT`
  (владелец) и добавить тренерские `POST /trainer/workouts/:id/start` и `finish`
  (только клиент тренера по активной связи `ClientTrainer`).
- [x] Статус тренировки общий: кто первый нажал «Начать»/«Закончить», тот и
  переводит `PLANNED → IN_PROGRESS → DONE`; второму участнику возвращать текущее
  состояние или `409`, данные не дублировать.
- [x] Разрешить тренеру записывать результаты: `PUT /trainer/workout-items/:id/result`
  (или расширить существующий эндпоинт ролью `TRAINER` с проверкой доступа к
  клиенту). Блокировка после `DONE`/`SKIPPED` — как в п. 1.
- [x] Не вводить ограничение «одна активная тренировка у тренера»: один тренер
  может одновременно иметь несколько тренировок в `IN_PROGRESS` у разных клиентов.
  Не добавлять unique-ограничения на `(trainerId, status)`.
- [x] Переходы статуса делать условным обновлением
  (`updateMany where { id, status: ожидаемый }`) и проверять `count`, чтобы
  исключить гонку одновременного старта/завершения тренером и клиентом.

### Мобильное приложение

- [x] Клиент: `PLANNED` → кнопка «Начать тренировку»; после старта открывается
  пошаговый режим заданий (упражнение за упражнением, кнопки «Далее»/«Назад»,
  индикатор прогресса), отметка выполнения, факт. вес/повторения/комментарий,
  в конце — «Закончить тренировку».
- [x] Тренер: экран со списком своих клиентов и их тренировок на день; для
  каждого клиента отдельная кнопка «Начать тренировку»; несколько тренировок
  могут быть `IN_PROGRESS` одновременно.
- [x] Тренер: переключение между активными клиентами без потери введённых данных,
  у каждого клиента свой прогресс и свой экран заданий.
- [x] Для `DONE`/`SKIPPED` — только чтение, без кнопок сохранения и завершения.
- [x] Состояние пошагового выполнения хранить по `workoutId`/`itemId`, не в
  глобальном синглтоне, иначе несколько клиентов у тренера перемешаются.

### Тесты и документация

- [x] Расширить `backend/src/workouts/workout-lock.e2e-spec.ts`:
  - тренер и клиент могут начать одну и ту же тренировку; при одновременном
    старте один запрос успешен, второй — `409`/текущее состояние;
  - тренер не может начать/завершить тренировку чужого клиента (`403`);
  - тренер ведёт две тренировки разных клиентов одновременно — обе в
    `IN_PROGRESS`, результаты не смешиваются;
  - тренер записывает результат, после `finish` получает `409`;
  - клиент видит тренировку, начатую тренером, в статусе `IN_PROGRESS`.
- [x] Обновить `docs/api.md`: тренерские start/finish и запись результатов,
  правила доступа и `409`.
- [x] Обновить `docs/er.md`: общий жизненный цикл тренировки для клиента и тренера.

Критерий приёмки:

- и тренер, и клиент запускают тренировку из мобильного приложения;
- после старта задания открываются и выполняются поэтапно;
- тренер одновременно ведёт несколько клиентов, данные и прогресс не смешиваются;
- завершённая тренировка неизменяема для обеих ролей.
