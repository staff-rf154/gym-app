## 2. Согласовано (см. `docs/verdikt2.md`)

| # | Область | Решение | Что меняется в ТЗ | Приоритет |
|---|---------|---------|-------------------|-----------|
| 1 | GymLinks | Клиент может сам выбрать тренера (`assignedBy=CLIENT`) | Раздел 2, 3, 4.3, API `client` | P1 |
| 2 | Reports | Агрегация в PostgreSQL, тяжёлые отчёты — с обязательным периодом | NFR раздела 5 | P1 |
| 3 | API | Единый контракт `page`/`limit` + `items/total` для клиентов, тренеров, тренировок, чатов, уведомлений | NFR раздела 5, API | P1 |
| 4 | Trainers | Мягкое удаление с сохранением истории; архивный тренер не входит | Раздел 4.2, модель Trainer | P1 |
| 5 | Gyms | Поведение `isActive` не меняем; в ТЗ зафиксировано как информационное в MVP | Раздел 4.1 | P2 |
| 6 | Redis | Распределённый throttler + кеш справочников/отчётов | NFR раздела 5 | P2 |
| 7 | Web-admin | Сброс пароля в карточках клиента/тренера/ресепшена | Разделы 8, 10 | P1 |
| 8 | Mobile | Смена пароля в настройках; lazy-вкладки; подгрузка истории чата | Разделы 5, 8, 10 | P2 |
| 9 | Mobile | Полный сброс пользовательских кешей при logout | NFR раздела 5 | P2 |
| 10 | Notifications | Inbox и отметка о прочтении для всех ролей | Разделы 2, 3, 4, API | P1 |
| 11 | Tests | Отдельная БД `gym_test` для e2e | NFR раздела 5, раздел 9 | P2 |
| 12 | Security | `pg_hba` без `trust`, только `scram-sha-256` | Раздел 9 | P1 |

(ресепшен — только клиентам своего зала); админский и ресепшен-эндпоинты
возвращены задачей 018.

## 3. Предлагаемые улучшения сверх ТЗ

1. Кешировать справочники (залы, упражнения, оборудование) в Redis с инвалидацией по mutation.
2. Вынести отчёты в материализованные представления/периодический пересчёт при росте данных.
3. Добавить `pino`-логи с request-id и метрики длительности Prisma-запросов.
4. Ввести фоновую очистку истёкших refresh-токенов и старых уведомлений.
5. Добавить индексы `pg_trgm` для поиска по названиям упражнений/продуктов при росте каталога.
6. Ограничить размер страниц API и добавить `Retry-After` для throttler.
7. Ввести healthcheck БД/Redis в `/health` (readiness/liveness раздельно).
8. Добавить CI: build + e2e + flutter analyze + web build на каждый PR.
