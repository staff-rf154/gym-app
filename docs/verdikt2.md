# Verdikt 2 — решения по расхождениям аудита 015

Дата: 2026-11-13. Задание: `docs/016_task_tz-disagreements.md`.

## Блок 1. Доступы и API

**Вопрос 1. Может ли клиент сам привязаться к тренеру?**
Ответ: разрешить клиенту. Связь может создаваться клиентом (`assignedBy=CLIENT`),
а также ADMIN/RECEPTION. ТЗ обновить, код уже поддерживает.

**Вопрос 2. Кто добавляет замеры веса?**
Ответ: тренер, админ и ресепшен. Ресепшен — только клиентам своего зала.
ТЗ расширить; код админского/ресепшен-эндпоинта вернуть отдельной задачей.

**Вопрос 3. Пагинация списков?**
Ответ: единый контракт `page`/`limit` для клиентов, тренеров, тренировок,
чатов, уведомлений. ТЗ дополнить; реализация — отдельной задачей.

**Вопрос 4. Агрегация отчётов?**
Ответ: агрегация в PostgreSQL (`groupBy`/SQL), без загрузки всех строк в память;
для тяжёлых отчётов обязателен период. ТЗ дополнить NFR.

## Блок 2. Данные и эксплуатация

**Вопрос 5. Удаление тренера с историей?**
Ответ: мягкое удаление (архивирование). История тренировок, замеров и
результатов сохраняется; архивный тренер не входит и не получает доступ.

**Вопрос 6. Активность зала (`isActive`) вне списков?**
Ответ: не менять текущее поведение. В ТЗ зафиксировать, что в MVP `isActive`
влияет на отображение/доступность в справочниках, но не блокирует исторические
операции и прямые ссылки.

**Вопрос 7. Redis?**
Ответ: использовать для распределённого throttler и кеша справочников/отчётов
с инвалидацией при изменении. Чат остаётся без Redis pub/sub (один инстанс).

**Вопрос 8. UI паролей?**
Ответ: web — сброс пароля админом/ресепшеном; mobile — смена пароля
пользователем в настройках. Оба входят в MVP.

## Блок 3. Клиенты и инфраструктура

**Вопрос 9. Кеш mobile при logout?**
Ответ: полный сброс сессии — при выходе очищаются все пользовательские
провайдеры/кеши; `autoDispose` используется как дополнение.

**Вопрос 10. Inbox уведомлений?**
Ответ: все роли — клиент, тренер, админ, ресепшен видят входящие уведомления
и отметку о прочтении. Рассылка по-прежнему у админа.

**Вопрос 11. БД для e2e?**
Ответ: отдельная тестовая БД (`gym_test`) в compose/CI; `make test` не должна
использовать рабочую БД.

**Вопрос 12. `pg_hba` trust?**
Ответ: убрать `trust`, использовать `scram-sha-256` для всех подключений;
PostgreSQL слушает только localhost (уже в compose).

## Блок 4. Frontend и объём

**Вопрос 13. Оптимизации frontend в MVP?**
Ответ: да — code-splitting web, lazy-вкладки mobile, подгрузка истории чата.

**Вопрос 14. Что делать сразу?**
Ответ: только обновить ТЗ. Код по решениям — отдельным заданием 017.
