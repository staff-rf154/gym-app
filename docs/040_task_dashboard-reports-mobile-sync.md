## Сжатая формулировка

1. **Отчёты**: проверить работоспособность всех отчётов, вывести их на
   дашборд web-admin, добавить экспорт PDF для отчётов посещаемости,
   оборудования и тренеров; исправить существующий PDF-экспорт.
2. **Быстрые действия**: вынести из `Dashboard.tsx` в общий компонент,
   разместить вверху и закрепить на всех защищённых страницах.
3. **Mobile**: добавить период «Прошлая неделя» во все разделы, где есть
   фильтр периода (тренировки, вес, отчёты/прогресс, уведомления, чаты),
   включая PDF.
4. **Mobile чаты**:
   - тренер: тренер↔клиент, тренер↔администратор зала,
     тренер↔системный администратор;
   - клиент: клиент↔тренер, клиент↔администратор зала.
5. **PDF**: найти и устранить причину неработающего экспорта, покрыть тестом.
6. **Сервер**: добавить очередь фоновых/синхронизационных операций
   (BullMQ + Redis) с ограничением параллелизма и чанкованием массовых
   записей, чтобы исключить блокировки БД при >1000 клиентах, ~500
   тренерах, >100 залах; добавить недостающие индексы.
7. **README**: переписать корневой `README.md` с нуля, без следов
   дописывания.
8. **Финал**: тесты (backend e2e, web-admin lint/build, flutter
   analyze/test), релиз (Docker Compose, mobile), коммит и push в git.
