# bug6 — Полный e2e удаляет демо-данные и профили администраторов

Дата: 2026-11-16
Связанное задание: 039

## Симптом

После полного прогона backend e2e на БД `gym`:

- количество залов стало 0, пользователей — 2;
- исчезли демо-залы, клиенты, тренеры и администраторы;
- пользователь `+73830000000` (Иванов Антон, роль `ADMINISTRATOR`,
  создан 2026-11-12) остался без профиля `Administrator`.

## Причина

`backend/src/demo/demo.e2e-spec.ts` в рамках сценария вызывает
`demoService.clear()`. Метод `clear()` в `backend/src/demo/demo.service.ts`
удаляет `Administrator` не только по `userId` демо-пользователей, но и по
`gymId` демо-залов:

```ts
await tx.administrator.deleteMany({
  where: {
    OR: [
      { userId: { in: userIds } },
      { gymId: { in: gymIds } },
    ],
  },
});
```

Поэтому при прогоне на рабочей/демо-БД удаляются администраторы, привязанные
к демо-залам, даже если их пользователи не являются демо-данными. Затем
удаляются сами демо-залы и пользователи.

Команда из документации проекта запускает e2e на `DATABASE_URL` БД `gym`,
а не на отдельной `gym_test`.

## Восстановление

- Демо-набор повторно загружен через `POST /admin/demo/load`
  (3 зала, 6 тренеров, 20 клиентов, 3 администратора, 780 тренировок).
- Профиль `+73830000000` автоматически не восстанавливался: неизвестен зал,
  к которому он был привязан. Требуется уточнение у владельца данных.

## Рекомендации

1. Запускать e2e только на отдельной БД `gym_test` (как указано в `docs/TZ.md`).
2. Добавить защиту в `demo.clear()` или e2e-конфигурацию: запрещать очистку
   демо-данных при `NODE_ENV !== 'test'` и/или не удалять `Administrator`
   по `gymId`, если пользователь не из демо-набора.
3. При необходимости восстановить профиль `+73830000000` вручную, указав зал.

## Проверки

- Воспроизведено полным прогоном:
  `pnpm test:e2e --runInBand --forceExit` на БД `gym`.
- После восстановления демо: 3 зала, 31 пользователь, 3 профиля
  `Administrator`, 20 клиентов, 6 тренеров, 780 тренировок.
