Что изменилось:

- **Auth.** Было: нет смены пароля клиентом, сброса пароля в admin/reception,
  logout; refresh из cookie передавал пустую строку и отзывал все сессии.
  Стало: `POST /auth/change-password`, `POST /auth/logout`, сброс пароля
  администратором/ресепшеном; refresh корректно читает cookie; смена и сброс

- **Seed.** Было: каждый старт backend перезаписывал пароль и timezone админа.
  Стало: seed не трогает `passwordHash`/`timezone`.
- **Клиенты/тренеры.** Было: `startWeight` можно было изменить, в ответах
  отдавался `passwordHash`, при отсутствии env использовался пароль-заглушка.
  Стало: `startWeight` неизменяем, `user` отдаётся только безопасными полями,
  пароль берётся только из `DEFAULT_CLIENT_PASSWORD`.
- **Reception.** Было: списки фильтровались в памяти и отдавали чужие залы,
  не было карточки клиента и сброса пароля. Стало: фильтрация в Prisma по
  своему залу, `GET /reception/clients/:id`, сброс пароля клиента/тренера.
- **Замеры веса.** Было: админ мог создавать замер. Стало: создание только
  тренером при активной связи; admin API и форма web-admin — только просмотр.
- **Тренировки.** Было: редактирование начатой тренировки удаляло результаты
  клиента. Стало: редактирование только в статусе `PLANNED`, иначе 409.
- **Чаты.** Добавлен `POST /chats` с проверкой роли и активной связи
  клиент-тренер, дедупликацией чата.
- **Уведомления.** Создание уведомления и получателей выполняется в транзакции;
  inbox остаётся клиентским, как в ТЗ.
- **БД.** Добавлены индексы по внешним ключам/датам и миграция
  `20261112130000_perf_indexes`.
- **Питание.** Дата «сегодня» по умолчанию считается в timezone пользователя.
- **Инфраструктура.** `restart: unless-stopped`, healthcheck backend/web-admin,
  корректный порядок запуска, nginx: лимит тела 6 МБ, прокси `/socket.io/`,
  gzip и кэш assets; Swagger управляется `ENABLE_SWAGGER`; env-пример без
  рабочих паролей.
- **Web-admin.** Logout вызывает backend и отзывает refresh-cookie; страница
  замеров веса переведена в просмотр.
- **Mobile.** Отчёты используют реальный идентификатор сессии, провайдеры
  reports/nutrition/chats получили `autoDispose`.

Схема данных: добавлены только индексы, поля не менялись.

## 017 — кэш авторизации web-admin на 10 часов (2026-11-13)

- **Web-admin.** Профиль пользователя (без токенов) кэшируется в
  `localStorage` на 10 часов. При перезагрузке в течение этого срока
  `/auth/me` не вызывается; access-токен остаётся в памяти и обновляется
  через httpOnly refresh-cookie. По истечении TTL кэш очищается, logout
  и неудачный refresh также очищают кэш.

## 019 — пагинация списков (2026-11-13)

- **API.** Клиенты, тренеры, тренировки, чаты и уведомления принимают
  `page` (с 1) и `limit` (по умолчанию 20, максимум 100) и возвращают
  `{ items, total, page, limit }`. Фильтры зала/клиента/периода сохранены.
- **Web-admin.** Списки и справочники отчётов читают `items`; таблицы
  запрашивают до 100 записей.
- **Mobile.** Чаты, уведомления и тренировки читают `items` и запрашивают
  `limit=100`.
- **Ограничение.** Постраничные переключатели в таблицах web-admin пока
  не добавлены; API к ним готов.

## 020 — SQL-агрегация отчётов (2026-11-13)

- **Backend.** Отчёты посещаемости, использования оборудования и по
  тренерам считают итоги, уникальных клиентов и динамику в PostgreSQL
  (`groupBy`/`GROUP BY`, `date_trunc`), без загрузки всех тренировок
  в память.
- **API.** Для `GET /reports/attendance`, `/reports/equipment-usage` и
  `/reports/trainers` обязательны `from` и `to` (YYYY-MM-DD). Проверка
  прав выполняется раньше проверки периода: чужой зал → 403, без
  периода → 400.
- **Web-admin.** Изменений не потребовалось: страницы отчётов уже
  передают выбранный период.
- **Ограничение.** Период обязателен для всех ролей, включая ADMIN.

## 022 — интеграция Redis: throttler и кеш (2026-11-13)

- **Инфраструктура.** `RedisModule` подключён в `AppModule`;
  `ThrottlerModule` использует `RedisThrottlerStorage`, счётчики
  rate-limit общие для всех инстансов backend. При недоступном Redis
  throttler переходит на in-memory fallback.
- **Кеш.** Справочники (`/gyms`, `/exercises`, `/food-products`, цели)
  кешируются на 5 минут; отчёты — на 60 секунд с ключом по пользователю,
  роли и параметрам запроса.
- **Инвалидация.** После успешных POST/PUT/PATCH/DELETE глобальный
  interceptor сбрасывает связанные префиксы кеша: изменения залов,
  упражнений, продуктов и целей — свои справочники; изменения клиентов,
  тренеров, тренировок, оборудования, связей с залами и демо-данных —
  кеш отчётов.
- **Конфигурация.** В Docker Compose backend получил `REDIS_HOST`,
  `REDIS_PORT`, `REDIS_PASSWORD`. В тестах ключи изолированы namespace
  процесса.
- **Совместимость.** Контракты API не изменились; TTL и инвалидация
  прозрачны для клиентов.
- **Исправление.** Вход тренера без профиля `Trainer` больше не
  блокируется как «архивный» (см. `docs/bug1.md`).

## 024 — сохранение авторизации web-admin при перезагрузке (2026-11-13)

- **Причина.** Refresh-cookie ставилась с `Secure` из-за
  `NODE_ENV=production`, но web-admin открыт по HTTP; браузер отбрасывал
  cookie, и `/auth/refresh` после `Ctrl+R` возвращал 401.
- **API.** `Secure` у `refresh_token` теперь зависит от фактического
  протокола: `X-Forwarded-Proto` (nginx) или `request.secure`. По HTTP
  cookie без `Secure`, по HTTPS — с `Secure`.
- **Совместимость.** Клиентский кэш профиля на 10 часов, TTL
  refresh-токена и контракты API не изменились.
- **Тесты.** Добавлены проверки атрибутов cookie и refresh по cookie;
  `auth` e2e — 12/12 passed. См. `docs/bug2.md`.
